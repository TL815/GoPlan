# GoPlan 产品需求文档

## 1. 文档摘要

GoPlan 是一款面向自由行用户的 AI 智能旅游攻略规划应用。用户输入目的地、出行天数及偏好后，系统自动生成含景点、住宿、美食、交通的完整行程，并在地图上可视化展示路线。本文档定义 GoPlan v1.0 MVP 及后续版本的功能范围、目标用户、成功指标与发布节奏。

## 3. 背景

### 3.1 市场机会

2024年国内出游人次达56.15亿，旅游收入5.75万亿元，同比增长17.1%。35岁以下人群占旅游消费主体的68%，其中自由行比例持续攀升。用户在出行前平均浏览15-30篇小红书/公众号攻略，但存在三个核心痛点：

- **信息碎片化**：攻略散落在小红书、公众号、朋友圈等平台，整合成本极高
- **规划缺工具**：从"种草"到"可出发"之间存在产品断层——收藏夹里一堆笔记，但没有工具能转换成可执行的行程
- **协作困难**：多人出行时，行程沟通依赖微信群聊来回转发，效率低下且容易遗漏

### 3.2 为什么现在做

- AI/NLP 能力已成熟到可精准提取攻略中的地点和时序信息
- 高德地图 SDK 提供成熟的坐标匹配、路线规划和实时交通能力
- 竞品"圆周旅迹"已验证"攻略解析→地图行程"这一产品形态的市场需求（MAU 约249万），但其纯工具定位留出了"AI对话 + 社交协作"的差异化空间
- Flutter 跨平台框架成熟，可实现一套代码覆盖 Android/iOS，降低初期研发成本

### 3.3 竞品格局

| 维度 | 圆周旅迹 | 马蜂窝AI | 飞猪问一问 | GoPlan 差异化 |
|------|:--------:|:--------:|:----------:|:------------:|
| 攻略解析 | 强（跨平台链接） | 社区内 | 无 | 同等+AI对话增强 |
| AI生成行程 | 地图节点 | 文字 | 文字+预订 | **AI对话式+地图节点** |
| 设计品质 | 极简工具风 | 信息密集 | 商业驱动 | **Dribbble级视觉设计** |
| 多人协作 | 支持 | 弱 | 不支持 | **实时协作+行程共享** |
| 商业干扰 | 零 | 重 | 最重 | 规划阶段零商业 |
| 社交属性 | 无 | 强（社区） | 无 | **旅行灵感Feed** |

## 4. 目标

### 4.1 产品目标

打造一款"规划体验最好看的AI旅行助手"——让做攻略从一件苦差事变成一种期待。通过 Dribbble 级的精致设计 + AI 智能规划能力，让用户从"打开App"到"拥有完整行程"的体验流畅、愉悦、有惊喜感。

### 4.2 成功指标（OKR）

**O1：产品完成从原型到可用MVP的跨越**

- KR1.1：完成 v1.0 全部核心功能开发并通过 QA 验收
- KR1.2：完成 Android/iOS 双端适配，Mock地图替换为真实高德地图
- KR1.3：内部20人可用性测试，任务完成率 ≥ 85%

**O2：核心规划体验达到可用水平**

- KR2.1：AI对话生成行程的成功率 ≥ 90%（正常输入下产出有效行程）
- KR2.2：从打开App到生成第一份行程的平均耗时 ≤ 120秒
- KR2.3：行程中POI坐标匹配准确率 ≥ 85%

**O3：建立高品质设计标准**

- KR3.1：UI还原度 vs Dribbble设计稿 ≥ 90%（像素级对比）
- KR3.2：关键页面加载时间 ≤ 1.5秒
- KR3.3：动画帧率稳定在 60fps

## 5. 目标用户

### 5.1 核心用户群

**主要用户：自由行规划者（22-35岁）**

- 特征：出行前习惯搜集大量攻略笔记，但对碎片化信息感到焦虑
- 行为：在小红书/公众号/抖音收藏旅行笔记，出行前需要花2-5小时整合
- 痛点：攻略太多不知道哪个靠谱、不知道路线是否合理、多人协调困难
- 场景：闺蜜游、情侣游、家庭游、毕业旅行、独自旅行

**次要用户：旅行灵感探索者（20-28岁）**

- 特征：有出行意愿但缺乏具体目的地想法
- 行为：刷旅行内容获取灵感，看到好看的目的地想"mark"
- 痛点：灵感散落各处，需要时找不到

### 5.2 用户故事地图

```
发现灵感 → 收藏目的地 → AI生成行程 → 手动微调路线 → 邀请好友协作 → 出行导航 → 旅行记录
  │            │              │               │              │            │          │
灵感Feed   收藏夹/bookmark  AI对话/攻略解析  地图拖拽排序   分享邀请链接  地图导航   照片+笔记
```

## 6. 价值主张

### 6.1 用户价值

| 维度 | 现有体验 | GoPlan 体验 |
|------|---------|------------|
| 攻略整合 | 手动在多个App间复制粘贴，耗时2-5小时 | AI一键解析，30秒生成行程框架 |
| 路线合理性 | 到了当地才发现景点之间不顺路 | 地图可视化+自动路径优化，规划阶段即发现问题 |
| 视觉体验 | 工具型App设计感较弱 | Dribbble级精致设计，规划本身就是一种享受 |
| 协作效率 | 微信群聊反复转发讨论 | App内实时协作，一人编辑全员同步 |
| 商业干扰 | 到处是酒店/门票预订推荐 | 规划阶段零商业，纯粹专注行程本身 |

### 6.2 与圆周旅迹的核心差异

- **设计驱动**：圆周旅迹是极简工具风，GoPlan 追求 Dribbble 级视觉品质——让"好看"成为产品的核心记忆点
- **AI 对话优先**：圆周旅迹的核心是"粘贴攻略链接→解析"，GoPlan 在此基础上增加 AI 自然语言对话能力——用户可以像跟朋友聊天一样描述旅行想法
- **灵感发现**：圆周旅迹没有内容发现功能，GoPlan 提供旅行灵感Feed，降低"不知道去哪"的启动门槛

### 7.1 产品架构

```
GoPlan
├── 启动页（品牌动画）
├── 首页
│   ├── 用户信息 & 天气

│   ├── AI建议/优化
│   ├── 天气信息
```

### 7.3 用户流程

**核心流程：从"想去"到"可出发"**

```
用户打开App
    │
    ├─→ 首页AI入口 → 输入"想去云南玩7天，喜欢拍照和美食"
    │       │
    │       └─→ AI生成行程草稿 → 在地图上展示路线
    │               │
    │               ├─→ 拖拽调整顺序 → 添加/删除地点
    │               ├─→ 邀请好友协作 → 好友收到通知加入编辑
    │               └─→ 确认行程 → 生成海报分享
    │
    ├─→ 粘贴小红书链接 → AI解析攻略 → 同上编辑流程
    │
    └─→ 浏览灵感Feed → 收藏目的地 → 新建行程 → AI生成
```

### 7.4 关键假设

| 假设 | 验证方式 | 风险 |
|------|---------|------|
| 用户愿意在规划App中输入文字描述需求 | 内测用户行为数据 | 中：部分用户可能更习惯浏览而非对话 |
| AI生成行程的质量能超过用户手动规划 | 内测满意度问卷 | 高：AI可能忽略个性化偏好 |
| Dribbble级设计能成为获客差异化优势 | 用户访谈+App Store评分 | 低：视觉品质是客观可衡量的 |
| 攻略链接解析的准确率能满足用户预期 | 100篇不同来源攻略测试 | 中：非标格式可能解析失败 |
| 多人协作是真实刚需而非伪需求 | 内测用户使用频率统计 | 中：独行游客不需要协作 |

## 8. 发布计划

### 8.1 版本节奏

| 版本 | 时间范围 | 内容 |

| v0.5 Alpha | 4周 | AI对话框架+行程数据模型+本地存储 |
| v0.8 Beta | 8周 | 真实地图集成+AI行程生成+行程编辑+行程卡片 |
| v1.0 MVP | 12周 | 完整核心流程+攻略解析+分享海报+内测发布 |
| v1.1 | 16周 | 多人协作+灵感Feed+性能优化+Bug修复 |

### 8.2 v1.0 功能范围确认

v1.0 MVP 包含：启动品牌页、首页（行程列表+天气+AI入口）、探索页（真实地图+POI筛选）、行程详情页（多日折叠+路线可视化）、AI对话页（行程生成+攻略解析）、个人中心（基础信息）、行程分享海报。

v1.0 不包含：多人协作、离线地图、费用分摊、旅行日记、灵感Feed。

### 8.3 技术与基础设施依赖

- 高德地图 Android/iOS SDK 集成（需轮换现有Key）
- AI服务后端（LLM接入+攻略NLP解析）
- 用户系统（注册/登录/Token管理）
- 云端数据存储（行程数据+用户数据+POI库）
- CDN图片存储（用户头像+行程封面+海报生成）
